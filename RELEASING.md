# Подготовка и публикация NSPD Fetcher

## Текущее состояние

Подготовлен экспериментальный выпуск **0.1.0** для QGIS **3.40–3.x**.
Исходники и трекер ошибок: [boxargus-png/NSPD_Fetcher](https://github.com/boxargus-png/NSPD_Fetcher).
Автор — **boxargus-png**, контакт — **boxargus@gmail.com**. Контакт обновлён
по указанию автора перед публикацией. URL репозитория, README и Issues указаны в
`metadata.txt`. Финальный архив — `dist/NSPD_Fetcher-0.1.0.zip`.
Загрузка в каталог QGIS и одобрение модератором ещё не выполнены.

Код уже содержал уведомления GPL-2.0-or-later. Файл `LICENSE` содержит полный
[официальный текст GPL-2.0](https://www.gnu.org/licenses/old-licenses/gpl-2.0.txt).
Условия «или более поздняя версия» сохранены в заголовках исходников и метаданных.

Проверки подготовки 17.10.2026: **111 тестов прошли** на Windows / QGIS 3.40.4.
Архив содержит 24 файла. Код из распакованного ZIP прошёл два цикла загрузки,
открытия формы и выгрузки через `qgis.utils`. Максимальное отклонение координат
эталона после цепочки МСК и округления — `1.1641532182693481e-10 м`.
Отдельно 5 проверок сборщика прошли в обычном Python 3.14 без PyQGIS.

## Порядок выпуска

1. Проверить, что репозиторий, README и Issues открываются без входа в аккаунт
   и соответствуют `repository`, `homepage`, `tracker` в `metadata.txt`.
2. Обновить версию и изменения в `metadata.txt`, README и CHANGELOG.
3. Проверить имя автора, контакт, название, уникальность версии в каталоге и
   сохранить `experimental=True` для первого экспериментального выпуска.
4. Добавить исходники в репозиторий, включая тесты и минимальную геометрическую
   фикстуру. Не включать рабочие журналы, исходные выписки, профили, каталоги
   `build`/`dist` и ZIP-файлы в историю Git. Релизный ZIP размещается как вложение
   к выпуску, а не как файл исходного кода.
5. Выполнить проверки ниже, затем зафиксировать соответствующую версию исходников
   и тег `v0.1.0`. Архив должен соответствовать этим исходникам.
6. Разместить ZIP и SHA-256 в выпуске репозитория. Войти с OSGeo ID в
   [каталог плагинов QGIS](https://plugins.qgis.org/), загрузить ZIP через
   **Upload a plugin** и дождаться решения модератора.

Публичные ссылки, короткое английское описание, документация и совместимая
лицензия требуются [правилами каталога QGIS](https://plugins.qgis.org/docs/publish).
Структура ZIP с одной папкой и файлами `metadata.txt`, `__init__.py`, `LICENSE`
описана в [документации QGIS](https://docs.qgis.org/3.40/en/docs/pyqgis_developer_cookbook/plugins/releasing.html).
Подготовка сборки сама по себе ничего не публикует и не отправляет.

## Проверки и сборка

Из корня репозитория, PowerShell / Python QGIS 3.40.4:

```powershell
& 'C:\Program Files\QGIS 3.40.4\bin\python-qgis-ltr.bat' -B -m unittest discover -s tests -v
```

Тесты используют изолированный профиль и локальный HTTP-сервер. Запросов к
НСПД нет. В набор входит эталон `52:18:0050232:698`, строгий отбор по охвату,
сохранение частичных результатов, прогресс и жизненный цикл интерфейса.
Проверки Linux/macOS пока отложены; эти платформы нельзя отмечать как проверенные.

Предварительная локальная сборка (при необходимости):

```sh
python -B scripts/build_release.py --allow-unpublished
```

Финальная сборка для публикации:

```sh
python -B scripts/build_release.py
```

Скрипт использует список `pb_tool.cfg`, проверяет обязательные файлы и локальные
импорты, создаёт ZIP, `.zip.sha256` и `.manifest.json` в `dist`. Манифест
перечисляет хеши исходных файлов и оставшиеся препятствия для публикации.
Сборщик не проверяет доступность URL и не заменяет модерацию QGIS.

Проверка финального архива:

```powershell
& 'C:\Program Files\QGIS 3.40.4\bin\python-qgis-ltr.bat' -B scripts/check_release.py dist/NSPD_Fetcher-0.1.0.zip
```

Она распаковывает ZIP в новый каталог `build/release-checks`, запускает отдельный
QGIS без видимых окон с этим профилем, загружает код только из архива, проверяет
инициализацию, открытие формы, выгрузку/повторную загрузку и цепочку МСК на
эталоне. Отчёт сохраняется рядом с профилем. Рабочий профиль пользователя не
затрагивается; это проверка развёрнутого содержимого архива, а не автоматизация
диалога «Установить из ZIP».

После изменений иконки: `pyrcc5 -o resources.py resources.qrc` из окружения QGIS.
Снимки реальной формы для страницы выпуска можно подготовить командой
`python -B -m tests.manual_ui_preview`; они появятся в `build/ui_preview`.
