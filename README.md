# NSPD Fetcher (Загрузчик НСПД)

Плагин для QGIS, предназначенный для удобной загрузки пространственных данных с [Национальной системы пространственных данных (НСПД / Публичной кадастровой карты)](https://nspd.gov.ru/).

QGIS plugin for downloading Russian cadastral features from NSPD by area or
cadastral number, with optional conversion to supported local MSK coordinate
systems. Russian interface; no additional Python packages. Requires QGIS
3.40–3.x and internet access. Tested on Windows with QGIS 3.40.4.

**0.1.0 — первый экспериментальный выпуск.**
[Исходный код](https://github.com/boxargus-png/NSPD_Fetcher) и
[трекер ошибок](https://github.com/boxargus-png/NSPD_Fetcher/issues) находятся на GitHub.
Плагин подготовлен к публикации в каталоге QGIS; загрузка в каталог ещё не выполнена.

## Возможности

* **Загрузка по охвату**: Скачивание данных в пределах нарисованного полигона или геометрий существующего векторного слоя. При наличии выделения используются только выбранные объекты; точки и линии буферизуются на 1 единицу EPSG:3857.
* **Загрузка по кадастровым номерам**: Поиск и скачивание геометрии и атрибутов по списку кадастровых номеров (ввод вручную или выбор из таблицы атрибутов слоя).
* **Автоматическое перепроецирование**: Конвертация полученных данных из Web Mercator (EPSG:3857) в выбранную вами Местную систему координат (МСК).
* **Разнообразие слоев**: Поддержка земельных участков, ОКС (здания, сооружения), единиц кадастрового деления (округа, районы, кварталы), территориальных зон, лесничеств, границ муниципалитетов и субъектов и многих других слоев.

## Установка

### Установка из файла (ZIP-архив)
1. Возьмите установочный архив `NSPD_Fetcher-0.1.0.zip` у автора или соберите его из исходников (команда ниже). После размещения архива он будет доступен в [Releases](https://github.com/boxargus-png/NSPD_Fetcher/releases). ZIP с исходным репозиторием не заменяет установочный архив.
2. В QGIS перейдите в меню **Модули** -> **Управление модулями**.
3. Выберите вкладку **Установить из ZIP** и укажите скачанный архив.

### Установка через официальный репозиторий QGIS
Пока недоступна. После публикации экспериментального выпуска потребуется
включить показ экспериментальных модулей в настройках менеджера модулей QGIS.

Результаты загружаются во **временные слои**. Чтобы они остались после закрытия
QGIS, сохраните их в GeoPackage или другой файл через меню экспорта слоя.

## Использование

1. Нажмите на иконку плагина на панели инструментов QGIS.
2. В окне **Загрузка данных НСПД** отметьте нужные категории в дереве **Данные НСПД** (например, "Земельные участки из ЕГРН" или "Кадастровые кварталы"). Под деревом показано число выбранных доступных категорий. Недоступные для текущего режима категории отключены; при возвращении к режиму по охвату их выбор восстанавливается.
3. Выберите режим работы во вкладках:
    * **По охвату**: Выберите **Нарисовать на карте** или **Из слоя**. При рисовании щелчки добавляют вершины, Enter завершает полигон, Esc отменяет рисование. Подсказка видна прямо на карте, заливка почти прозрачная. Готовый охват показан тонким контуром, а надпись «Охват задан» отмечена зелёной галочкой. Кнопка с лупой и рамкой приближает карту к охвату; изменить его можно кнопкой «Перерисовать». Отмена перерисовки сохраняет прежний охват. Смена CRS карты во время рисования отменяет незавершённый полигон, чтобы не смешать координаты.
    * **По кадастровым номерам**: Введите номера через запятую в текстовое поле или укажите векторный слой и целевое поле со списком кадастровых номеров.
4. Задержка между запросами находится в сворачиваемом блоке **Параметры загрузки**. По умолчанию пауза составляет 5–10 секунд; изменение компоновки не меняет её значение.
5. (Опционально) Включите "Преобразовать в МСК" в блоке **Результат** и выберите **МСК результата** с параметрами перехода ГОСТ 2008. Промежуточную систему с параметрами ГОСТ 2001 плагин создаёт автоматически. Округление координат до `0,01 м` можно отключить.
6. Нажмите **Загрузить данные** и дождитесь загрузки (новые временные слои автоматически добавляются на карту). Во время работы доступна кнопка **Отменить загрузку**, уже полученные результаты сохраняются. Кнопка **Журнал** открывает подробности выполнения.

В блоке **Ход загрузки** отображаются текущая категория и полигон охвата либо
кадастровый номер, этап обработки, время с начала загрузки и обратный отсчёт
паузы между запросами. Полоса показывает долю завершённых запросов, включая
запросы с ошибкой: для охвата это число полигонов × число категорий, для поиска
по номерам — число уникальных номеров. Это не прогноз оставшегося времени;
после запросов ещё может выполняться создание слоёв. При отмене или ранней
ошибке полоса остаётся на фактически достигнутом значении.

Счётчики показывают полученные записи, оставленные после пространственного
отбора, исключённые вне охвата, сохранённые без проверки, пустые ответы, ошибки
и добавленные слои. Записи считаются до удаления точных повторов. После
завершения в окне остаётся итоговый статус; новая загрузка сбрасывает счётчики.

Контур охвата скрывается при закрытии окна и выборе другого способа загрузки.
При повторном открытии окна он восстанавливается; его отображение следует за
CRS карты без изменения исходных координат охвата.

## Требования

* QGIS 3.40+ в ветке 3.x. Проверено на Windows с QGIS 3.40.4.
* Рабочее подключение к интернету для обращения к API НСПД.
* Доступный провайдер алгоритмов Processing `native`. HTTP-запросы выполняются средствами QGIS; установка `requests` не требуется.

QGIS 3.34 не поддерживается: регистрация обработчика HTTP-заголовков в его
Python API может аварийно завершать процесс ([QGIS #55329](https://github.com/qgis/QGIS/issues/55329)).
Защита по версии проверяется до вызова этого API. Linux, macOS и QGIS 4 пока
не проверялись.

### Структура кода

* `NSPD_Fetcher.py` — подключение к QGIS и жизненный цикл плагина.
* `NSPD_Fetcher_dialog.py` — форма, управление охватом, валидация и сообщения пользователю.
* `polygon_capture_tool.py` — рисование с подсказкой и прозрачной заливкой, контур готового охвата в CRS карты.
* `task_controller.py` — одна активная задача, доставка результатов в GUI и отмена при выгрузке плагина.
* `api_task.py` — обход полигонов/категорий или кадастровых номеров, прогресс и отменяемые задержки.
* `api_client.py` — формирование запросов, проверка структуры ответов и диагностируемые ошибки; транспорт можно подменять в тестах без QGIS.
* `qgis_network.py` — HTTP через `QgsBlockingNetworkRequest`, настройки сети QGIS и отмена через `QgsFeedback`.
* `fetch_result.py` — результаты запросов, состояния выполнения и неизменяемые снимки прогресса без зависимости от QGIS.
* `feature_dedup.py` — удаление только точных повторов исходных записей НСПД.
* `coverage.py` — перепроецирование охвата, буферизация, разбиение сеткой и сериализация полигонов с внутренними кольцами.
* `coverage_query.py` — расширение запросов и пространственный отбор ответов QGIS по всему охвату.
* `layer_manager.py` — подготовка атрибутов GeoJSON, обработка геометрий и добавление слоя в проект.
* `msk_transform.py` — проверка выбранной МСК и создание промежуточной CRS с параметрами ГОСТ 2001 в памяти.

При загрузке по охвату каждый полигон запроса расширяется примерно на **5 м на
местности**. Поправка на масштаб EPSG:3857 вычисляется по наиболее удалённой от
экватора границе полигона: `5 × cosh(|Y|max / 6378137)` единиц проекции
([формулы Web Mercator в PROJ](https://proj.org/en/stable/operations/projections/webmerc.html)).
Это фиксированный поисковый запас без настройки в форме; он не задаёт точность
границ и не гарантирует компенсацию любого ошибочно назначенного CRS.

Буфер используется **только для запроса**. Полученные геометрии проверяются
средствами QGIS по **исходному охвату**, после согласования координат и до
округления. Для охвата в поддерживаемой МСК ГОСТ 2008 копия геометрии ответа
переводится из EPSG:3857 в промежуточную МСК ГОСТ 2001 и сравнивается с исходными
числами охвата — так же, как в цепочке формирования результата. МСК определяется
по проверенным параметрам CRS, а не по названию. Для остальных CRS применяется
обычное преобразование ответа в систему охвата; для EPSG:3857 координаты остаются
без изменений. Выбор CRS результата на отбор не влияет. Происхождение ранее
перепроецированных данных в EPSG:3857 автоматически восстановить невозможно.

Учитываются все исходные полигоны и внутренние кольца; разбиение сеткой меняет
только запросы. Сохраняются пересекающие исходный охват объекты, включая касания;
объекты только из буфера исключаются. Отдельные слои и настройки не добавляются. Объекты
с пустой, отсутствующей или некорректной геометрией сохраняются без отбора, с
сообщением о невозможности проверки. При отмене во время проверки сохраняются
также ещё не проверенные записи уже полученного ответа. Геометрии объектов не
обрезаются, атрибуты не меняются. Поиск по кадастровым номерам не фильтруется.

После загрузки показываются количества записей внутри исходного охвата, исключённых
и сохранённых без проверки; эти числа считаются до удаления точных повторов.

Перед созданием каждого результирующего слоя удаляются только точные повторы
исходных записей: должны совпадать категория `properties.category`, ID объекта
`feature.id`, геометрия и все атрибуты. Сравниваются также дополнительные поля
ответа. Совпадение контура само по себе не приводит к удалению объекта. Если
категория или ID отсутствуют, пусты или имеют неподдерживаемый тип, обе записи
сохраняются. Допустимы целые числа и непустые строки; типы значений не приводятся.
Порядок ключей JSON не учитывается, порядок координат и элементов массивов
сохраняется. Проверка выполняется до округления и преобразования данных в QGIS,
включая повторы из разных ответов сервера, объединяемых в один слой.

Исходный ID НСПД сохраняется в атрибуте `nspd_id`, поскольку внутренние номера
объектов QGIS могут меняться. Если поле с таким именем уже есть, используется
свободное имя `nspd_id_2`, `nspd_id_3` и далее. В сообщении о загрузке указывается
число полученных записей до пространственного отбора и удаления повторов; в журнале отдельно отмечается
число удалённых повторов и объектов добавленного слоя.

Цепочка МСК: перепроецирование из EPSG:3857 в
автоматически созданную МСК с параметрами ГОСТ 2001 → округление с шагом `0.01 м`
(если включено) → назначение выбранной МСК результата. Назначение CRS не изменяет
координаты. При отключённом преобразовании в МСК результат остаётся в EPSG:3857;
те же правила удаления точных повторов действуют в обоих случаях.

Автоматическое создание поддерживает метрические МСК с `+proj=tmerc`,
`+ellps=krass` и известными параметрами
`+towgs84=23.57,-140.95,-79.8,0,0.35,0.79,-0.22`. Проверяются параметры CRS,
а не её название. В промежуточной CRS заменяется только `+towgs84` на
`23.92,-141.27,-80.9,0,0.35,0.82,-0.12`: зона, осевой меридиан, масштаб и смещения
сохраняются. Выбранная CRS не изменяется, новая запись в справочнике QGIS не
создаётся. Если система не выбрана или содержит неподдерживаемое преобразование,
загрузка не начинается и показывается ошибка.

Сетевые ошибки отделены от успешных пустых ответов. В режиме охвата завершённые
категории добавляются по мере загрузки. При ошибке запроса или отмене задачи
через панель задач QGIS уже полученные объекты незавершённых категорий тоже
добавляются на карту. При поиске по номерам все успешно полученные объекты
добавляются вместе, в том числе после отмены. Пустые слои не создаются;
ранее добавленные в рамках задачи категории повторно не публикуются.

Неполные результаты отмечаются в названии слоя «неполная загрузка» и свойстве
`nspd_fetcher/incomplete`; завершённые категории сохраняют обычное название.
Сообщение о завершении отдельно показывает отмену, ошибки и номера, для которых
сервер вернул корректный пустой ответ. Невыполненные и прерванные запросы не
попадают в список ненайденных. Правила удаления повторов и цепочка МСК одинаковы
для полных и частичных результатов. Слои остаются временными: для хранения после
закрытия QGIS их нужно сохранить в файл обычными средствами QGIS. Это сохранение
результата при завершении задачи, а не резервное копирование на диск при аварии
или выгрузке плагина.

Неизвестная структура JSON, явная ошибка сервера,
`features: null`, повреждённая структура координат или неожиданная явно указанная
CRS считаются ошибками ответа. Корректные пустые списки остаются результатом
«не найдено». Допустимая GeoJSON-геометрия `null` сохраняется.

Сетевой клиент использует прокси, доверенные сертификаты и таймаут из настроек
QGIS (по умолчанию 60 секунд без сетевой активности). Плагин не отключает
проверку TLS и не изменяет общие настройки сети. Ошибки TLS, таймаута, HTTP и
структуры ответа различаются в диагностике. Запросы выполняются без чтения
старого ответа из кэша; автоматических повторов нет. Прежний User-Agent НСПД
сохраняется через обработчик только помеченных запросов плагина: QGIS иначе
заменяет этот заголовок. Обработчик удаляется при выгрузке плагина.

Отмена задачи в панели задач QGIS и выгрузка плагина прерывают активный
HTTP-запрос. Отмена не записывается как сетевой сбой или ненайденный объект.
При отсутствии настройки языка используется системная локаль; после ошибки
создания диалога его можно открыть повторно.

### Проверки

Из корня репозитория:

```sh
python -B -m unittest discover -s tests -v
```

Без PyQGIS выполняются проверки HTTP-клиента на подставных ответах, удаления повторов, модели
результатов и состава сборки; интеграционные тесты пропускаются. Для полной
проверки нужно окружение Python из установки QGIS. Пример для PowerShell:

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
& 'C:\Program Files\QGIS 3.40.4\bin\python-qgis-ltr.bat' -B -m unittest discover -s tests -v
```

Тесты запускают отдельный экземпляр QGIS без видимого окна и без рабочего проекта,
с отдельным профилем в игнорируемом каталоге `build/test-profiles`.
Они проверяют цепочку МСК, геометрии охвата, фоновые задачи, состояние диалога и
обработку ошибок. Сетевые интеграционные тесты поднимают локальный HTTP-сервер
на `127.0.0.1` со случайным портом: проверяют GET/POST, заголовки, ошибки,
отмену во время ожидания ответа с сохранением предыдущих результатов, выгрузку
и цепочку МСК после загрузки. Диалог проверяется на сохранение полных и неполных
слоёв при ошибках и отмене в обоих режимах запросов. Им нужен
доступ к loopback-соединениям; запросов к НСПД нет. `test.py` в корне — отдельная
ручная проверка живого API через тот же клиент QGIS, в автоматический набор
не входит. Запускать её нужно Python из QGIS; выполняются GET по тестовому
участку и POST по его охвату.

Регрессионный пример `tests/fixtures/msk52_52_18_0050232_698.json` содержит геометрию
НСПД участка `52:18:0050232:698`, полученную 17.10.2026, и четыре координаты из
выписки 2024 года. Указаны происхождение данных и хеши исходных файлов; сведения
о правообладателях и прочие атрибуты в тест не включены. Номер зоны в выписке
пропущен: для проверки использована МСК-52, зона 2, согласующаяся с координатами
и соседним участком. После существующего округления цепочка воспроизводит все
четыре координаты до сантиметра. Без округления остаток около `0.09 мм`, при
прямом пересчёте с параметрами ГОСТ 2008 — около `0.639 м`. Это проверка
воспроизведения чисел из выписки, а не точности положения границ на местности.
Тест также сравнивает новую цепочку с прежним ручным выбором двух CRS.

Отдельный диагностический сценарий воспроизводит пропуск участка при узком
охвате в МСК: `python -B -m tests.manual_coverage_boundary`. Он создаёт охват с
заходом внутрь участка на 0,25 м и площадью пересечения 1 м², сравнивает текущую
подготовку координат **без поискового буфера** с обратной цепочкой ГОСТ 2001 и сохраняет GeoPackage, рисунок и
измерения в `build/coverage_boundary_52_18_0050232_698/<UTC-время>`.
Запускать нужно Python из QGIS 3.40+. С флагом `--live` дополнительно выполняются
шесть запросов к НСПД с паузами 2 секунды: проверка актуальности геометрии,
две пары сравнений и контроль с более глубоким пересечением. Тела запросов и
ответов сохраняются рядом с `summary.json`. Это ручная диагностика, не часть
автоматических тестов; она не меняет преобразования рабочего плагина.

Исправленный путь проверяет `python -B -m tests.manual_buffered_coverage`: запрос
с буфером, строгий локальный отбор, один результирующий слой и координаты эталона
после цепочки МСК. Дополнительно каждый полученный объект проверяется через
цепочку обработки слоя без округления: в результате должны остаться ровно те
объекты, которые пересекают исходный охват. С флагом `--live` выполняются три
запроса к НСПД с паузами 2 секунды:
поиск эталона, прежний охват без буфера и запрос через текущую фоновую задачу.
Ответы и итог сохраняются в `build/buffered_coverage_52_18_0050232_698/<UTC-время>`.

Предпросмотр реальной Qt-формы и контура на карте можно получить командой
`python -B -m tests.manual_ui_preview` из Python QGIS. Снимки разных режимов
сохраняются в `build/ui_preview`; используется отдельный тестовый профиль.
Снимки `progress_waiting.png` и `progress_partial.png` показывают реальную
фоновую задачу с локальными тестовыми ответами, без обращения к НСПД.

### Сборка установочного ZIP

Сборка работает на стандартной библиотеке Python, без `pb_tool`, `make` и
установки в рабочий профиль QGIS:

```sh
python -B scripts/build_release.py
```

В `dist` появятся `NSPD_Fetcher-0.1.0.zip`, его SHA-256 и JSON-манифест
с хешами включённых файлов. Используется явный список из `pb_tool.cfg`:
журналы, выписки, тесты, профили и содержимое `build` в архив не попадают.
Внутри ZIP находится одна папка `NSPD_Fetcher`, включая лицензию и документацию.

Сборщик откажется создавать релиз при пустых или шаблонных ссылках
`repository`, `homepage` и `tracker` в `metadata.txt`. Он проверяет структуру URL,
но не сетевую доступность: доступ к репозиторию и трекеру нужно проверить отдельно.
Флаг `--allow-unpublished` предназначен для локальных предварительных сборок;
их имя получает суффикс `-local`.

Проверка именно собранного архива в изолированном профиле (Python из QGIS):

```powershell
& 'C:\Program Files\QGIS 3.40.4\bin\python-qgis-ltr.bat' -B scripts/check_release.py dist/NSPD_Fetcher-0.1.0.zip
```

При добавлении модулей обновляйте `python_files` в `pb_tool.cfg` и `PY_FILES` в
`Makefile`; полнота обоих списков проверяется тестом. После изменения иконки
пересоберите `resources.py` через `pyrcc5 -o resources.py resources.qrc`.
`make test`, `make package` и `make package-local` вызывают те же проверки и
сборщик. Порядок публикации для сопровождающего находится в `RELEASING.md`
в исходном репозитории; этот файл не включается в установочный ZIP.
